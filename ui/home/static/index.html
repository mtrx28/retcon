Delete lookalikes, Invalidate one hop and Taint everything downstream are our reimplementations of how other systems retract, written for this benchmark, not their code.

  1. First it writes down why.

    Every fact is stored with the evidence behind it: which sources said it, and which agents repeated it.

  2. Then a source goes bad.

    You distrust one source for a window of time. Everything resting on it becomes tentative.

  3. It keeps what still stands.

    A fact that another source also supports comes straight back. A fact that only repeats itself does not.

  4. And it can undo itself.

    Nothing is deleted. Preview on a copy, commit, reinstate: the graph returns to exactly where it was.

Forgetting too much

A rule that taints everything downstream of a bad source also flags payments that are still correct.

 

Run python -m bench.harness.receipt to itemise this.

Every payment is a line somebody has to reconcile later. A rule that cannot tell a bad belief from a correct one makes that job bigger, not smaller.

RETCON asks one question of each memory: does anything independent still hold it up?

Measured, not claimed

  • Retracting takes milliseconds, not minutes.

    Time to retract one source, from a graph of a few dozen memories to ten thousand.

  • Real retractions, nothing left behind.

    Retracted papers from the Retraction Watch database, replayed on their real dates.

  • Writers pile on. Answers stay right.

    Many agents writing while a retraction runs, then every status checked against an independent recomputation.

  • Take the graph away and it pays the attacker.

    The same agents, the same attack, with similarity search instead of justifications.
